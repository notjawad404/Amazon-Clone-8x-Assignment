## 2. Core flow and the decisions it forces

```
Home ─► Search/Category ─► Product ─► Cart ─► [Login if guest] ─► Checkout ─► Confirmation ─► Orders
                               └──── Buy Now ─────────────────────────┘
```

- **Login is required only at checkout.** Guests can browse and build a cart. On login, the guest cart is merged into the user's cart (quantities added together and capped by stock).
- **Orders snapshot prices.** Each order line stores title, variant, unit price, and image at purchase time, so later product edits don't change order history.
- **Stock is checked twice.** Once on add-to-cart (soft check) and again inside a transaction when the order is placed (hard check, decrement stock). If an item sold out, the user is sent back to the cart with a message.
- **Totals are computed only on the server.** The client never sends prices. Tax uses a flat rate (e.g. 8%) and shipping uses fixed rules.
- **Buy Now** builds a one-off checkout session for a single item and leaves the cart alone, which matches Amazon.

## 3. Recommended stack

- **Next.js (App Router) + TypeScript**: SSR helps search and product pages, and server actions handle cart and checkout mutations.
- **Tailwind CSS**: makes it quick to match Amazon's dense layout. I'd copy the visual language (dark nav, yellow buttons) but use our own name and logo.
- **PostgreSQL + Prisma**. SQLite works for local dev if you want zero setup.
- **Auth.js (credentials provider)** or a hand-rolled session with bcrypt and an httpOnly cookie.
- **Zod** to validate forms and actions. **Vitest** for pricing and cart logic, **Playwright** for one end-to-end test of the core flow.
- **Seed data**: about 100–200 products across 6–8 categories (e.g. from DummyJSON / Fake Store API), with variants, images, and ratings.

## 4. Data model

```
User(id, name, email, passwordHash, createdAt)
Address(id, userId, fullName, line1, line2, city, state, zip, country, phone, isDefault)
Category(id, slug, name, parentId?)
Product(id, slug, title, brand, categoryId, description, bullets[], ratingAvg, ratingCount, createdAt)
ProductImage(id, productId, url, sortOrder)
Variant(id, productId, sku, name, attributes{color,size}, priceCents, listPriceCents?, stock, imageUrl?)
Review(id, productId, userId, rating, title, body, createdAt)   -- seeded, read-only in MVP
Cart(id, userId?, sessionId?) / CartItem(id, cartId, variantId, qty, savedForLater, addedPriceCents)
Order(id, number, userId, status, addressSnapshot JSON, deliveryMethod, deliveryEta,
      subtotalCents, shippingCents, taxCents, totalCents, paymentLast4, placedAt, shippedAt?, deliveredAt?, cancelledAt?)
OrderItem(id, orderId, variantId, titleSnapshot, variantSnapshot, imageSnapshot, unitPriceCents, qty)
```

Store money as integer cents. Every product has at least one variant, which keeps the cart and order code to a single path.

8. **Polish**: responsive layout, empty, loading and error states, 404s, basic accessibility, the Playwright test for the core flow, README.

Milestones 1–6 cover the core flow you described, and 7–8 complete the MVP.
